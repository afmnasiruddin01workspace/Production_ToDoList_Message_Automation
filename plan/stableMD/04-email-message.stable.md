# 04 — Email Message per Person

## 1. Frontmatter
See YAML header above. Every field must be filled before validation.

## 2. Goal
Send each person in `EmailContacts.txt` the same to-do list module 02 sends them on WhatsApp, as an **email from the owner's own Outlook mailbox**, in the layout of the owner's reference screenshot (`src/EmailContent/image.png`), on the weekdays chosen for that person in the email file — and record exactly what was sent, skipped, queued or bounced, in `send_log.json` and in the shared delivery ledger, for module 03 (scheduler) and module 05 (manual UI).

**Why Outlook itself, not SMTP.** The owner already sends this mail by hand from classic Outlook 16.0 against a single primary Exchange mailbox, with recipients resolved from the company address book. Sending through that same Outlook (COM automation) means: no password or app-token to store anywhere, the mail leaves exactly as a hand-sent one would (same From, same Sent Items copy, same address-book resolution), and the Sent Items folder becomes the proof of hand-over.

**What "delivered" can and cannot mean for email.** Outlook can prove the message was **handed to the mail server** (a copy appears in Sent Items) and can notice a **bounce** (a non-delivery report arriving in the Inbox). It cannot prove the person opened it. v0.1 deliberately records only what is provable: `accepted`, `queued`, `bounced` (§4). Delivery/read receipts are out of scope (§5).

| Delivery ledger | `outputs/delivery/delivery_log.json` | json | shared with module 02; rows with `channel: "email"` (R19) |

Entry fields: `person`, `status`, `item_count`, and depending on status `subject`, `message` (the plain-text body, as module 02 builds it), `sent_at`, `delivery`, `to_resolved` (true/false: Outlook matched the address to the address book), `resend`, `error`, `send_days`.

Statuses: `sent` · `dry-run` · `already_sent` · `skipped_day` · `skipped_no_items` · `skipped_no_contact` · `skipped_over_cap` · `invalid_address` · `failed` · `unconfirmed` (Outlook accepted the call but the message was found neither in Sent Items nor in the Outbox, so nobody can say where it went; treated like `sent` for idempotency and never re-sent automatically).

**`delivery` values (only on `sent` / `unconfirmed` entries):**
- `accepted` — a copy tagged with this run's marker was found in **Sent Items**: Outlook handed the message to the mail server. This is the strongest thing provable without a recipient's cooperation.
- `queued` — the message is still in the **Outbox** after `EMAIL_VERIFY_TIMEOUT` (Outlook offline, or not yet synchronised). It *will* go when Outlook reconnects; it counts as sent for idempotency.
- `bounced` — a non-delivery report for it arrived in the Inbox (R16). Set after the fact, by the end-of-run check or by `--reconcile`.
- `pending` — found nowhere (see `unconfirmed`).

Summary fields: `sent`, `dry_run`, `failed`, `unconfirmed`, `invalid_address`, `skipped`, `bad_days`, `accepted`, `queued`, `bounced`.

Field rules: **no email address is ever written** to the log, the ledger, stdout or any committed file (R20) — `to_resolved` is the only trace of the recipient. No phone number either: this module never keeps the `WhatsApp contact name` or `Number` columns.

## 5. Scope
**In scope**
- Reading module 01's output and the email contact file (own `Send days` column).
- Building, per person, an email that is **the module 02 message text** in the owner's layout (§6 R5): fixed subject, greeting + numbered list, signature.
- Sending through the owner's own classic Outlook in three modes (`dry-run`, `self`, `live`), with a cap and a short pause.
- Starting Outlook itself, safely, when it is not running (R12), and never hanging on it (R13).
- Proof of hand-over from Sent Items, detection of a queued message, detection of a bounce (R15, R16).
- Not sending the same person twice in a day (R10); `--people` / `--resend` / `--trigger` / `--reconcile` / `--check` for the manual UI and scheduler (R21).
- Writing `send_log.json` and the shared ledger (R18, R19).

**Out of scope**
- SMTP, Gmail, Microsoft Graph, or any credential-based sending — Outlook is the transport by decision.
- **New Outlook ("olk") and Outlook on the web** — COM automation exists only in classic Outlook; `--check` reports it plainly if classic Outlook is missing.
- **Delivery receipts and read receipts** (`OriginatorDeliveryReportRequested`, `ReadReceiptRequested`): this mailbox has never produced a single report in 120 days, requesting them would put four report mails a day in the owner's Inbox, and they still would not prove the person read it. Revisit only if the owner asks.
- Attachments, Cc/Bcc, replies, reading anyone's mail other than non-delivery reports of this module's own messages.
- Choosing recipients or content differently from module 02 (a change to the WhatsApp text is, on purpose, a change to the email text).
- Scheduling (module 03) and the manual UI itself (module 05).
- Messaging the owner's own group (`A F M Nasir Uddin`) and `No Name` — no contact row exists for them, same as module 02.

## 6. Requirements
| ID | Requirement (testable) |
|---|---|
| R1 | `EmailContacts.txt` is read as a tab-separated file with a header row (a UTF-8 BOM and CRLF are tolerated). Only `Person` and the **4th tab-field** are used; the 4th field is split on whitespace into `<address>` (first token) and `Send days` (the remaining tokens, rejoined). The `WhatsApp contact name` and `Number` fields are discarded unread — never stored, printed or logged. `Person` is matched case-insensitively and trimmed; a duplicate `Person` stops the run with an error. A row with a 4th field holding only an address gets "every day"; a missing 4th field gives `invalid_address`. |
| R2 | The address must be a single well-formed address (`name@host.tld`, no spaces, no `,` or `;`). Otherwise that person gets `invalid_address` (no send, error text never includes the address) and the run continues. |
| R3 | `Send days` follows module 02's rule exactly (`parse_days`: comma-separated 3-letter or full day names; `Daily`/`All`/empty = every day; an unknown token is listed in `summary.bad_days` and treated as "not today"). Today's weekday is taken in `Asia/Dhaka`. |
| R4 | Only groups matching a `Person` row in the **email** file are mailed. Any other group (including `A F M Nasir Uddin` and `No Name`) gets `skipped_no_contact`; a contact whose item list is empty gets `skipped_no_items`; a person whose email days exclude today gets `skipped_day`. A person present in WhatsApp contacts but not in the email file is **not** mailed. |
| R5 | **Message layout (matches `image.png`).** Subject, exactly: `Pending Task List, Please communicate if any obstacle and close the issue if finished.` Body: the plain text of module 02's `build_message(person, items, today)` (so `Hello <Person>,` / `Your pending items (<D Mon YYYY>):` / blank line / `N. <title>` lines, with the person's own `(Name)` group stripped), followed by **two blank lines** and the signature `Regards` / `A F M Nasir Uddin` / `HOD of Fastener Production` / `ID 9781`. Sent as **HTML** in font **Aptos 12 pt** (fallbacks Calibri, Arial), each line ended by `<br>`, all text HTML-escaped, Bengali and any non-ASCII text preserved. No Cc, no Bcc, no attachment, no Outlook auto-signature added. Subject and signature are defaults that `.secrets/email.env` may override (§7). |
| R6 | In `dry-run` mode **Outlook is never started, attached to, or touched** and no mail leaves the machine; every mailable person gets status `dry-run` with `subject` and `message` in the log. |
| R7 | In `self` mode every mail goes to `EMAIL_TEST_ADDRESS` instead of the person's own address, with the subject prefixed `[SELF-TEST for <Person>] `; the log still names the intended person. `self` without `EMAIL_TEST_ADDRESS` refuses to run. The value `me` means "the signed-in Outlook user's own address", resolved by the worker at run time, so the owner's address need not be written into any file. |
| R8 | In `live` mode each mail goes to the person's own address from Outlook's default account; the module never sets From / SentOnBehalfOf. |
| R9 | `EMAIL_MODE` must be exactly `dry-run`, `self` or `live`; missing, empty or unknown → refuse to run. There is no default that sends. |
| R10 | If `send_log.json` already records `sent`, `already_sent` or `unconfirmed` for a person on today's date **in a `live` run**, that person is `already_sent` — a re-run never sends a second copy. `self` and `dry-run` rows never count. (Same rule as module 02 R11.) |
| R11 | At most `EMAIL_MAX_PER_RUN` mails per run (default 10); the rest are `skipped_over_cap`. A random pause of `EMAIL_MIN_DELAY`–`EMAIL_MAX_DELAY` seconds (default 1–3) separates mails. |
| R12 | **Outlook readiness.** `Dispatch` is only ever called when `OUTLOOK.EXE` is already running, because a bare `Dispatch` on a closed Outlook blocks on a profile dialog (§3). If it is not running, the module starts `OUTLOOK.EXE /profile <name>` **minimised**, where `<name>` is `EMAIL_OUTLOOK_PROFILE` or, if unset, the registry `DefaultProfile`; then polls (every 2 s) until `Session` answers or `EMAIL_STARTUP_TIMEOUT` seconds (default 90) pass. Failure → the run stops with reason `outlook-unavailable`, **nothing sent**, nothing left half-started that this module can kill (it kills only an Outlook it started and that never became ready). An Outlook this module started is **left running after a normal run** (R15 needs the Outbox to flush; closing it could strand mail) and the run row records `outlook_profile_started: true`. If the hard ceiling of R13 has to kill the worker, an Outlook the worker started dies with the process tree — the run has already failed, and a message left in the Outbox goes out when Outlook is next opened. |
| R13 | **No unbounded wait.** All COM work happens in a child worker process (`email_worker.py`); the parent enforces a hard ceiling `EMAIL_STARTUP_TIMEOUT + n × (EMAIL_SEND_TIMEOUT + EMAIL_MAX_DELAY + EMAIL_VERIFY_TIMEOUT) + EMAIL_BOUNCE_WAIT + EMAIL_KILL_MARGIN` seconds (n = mails to send) and on expiry kills the worker's whole process tree. The worker rewrites its result file (temp file + rename) after **every** recipient and records the one in flight. After a kill the parent logs handled recipients as recorded, the in-flight one as `unconfirmed`, and the rest as `failed` ("worker killed after Ns — not attempted"), then exits non-zero. Each recipient's COM calls are additionally bounded by `EMAIL_SEND_TIMEOUT`; on expiry that person is `unconfirmed` and the run stops with reason `send-timeout`. |
| R14 | Per recipient the worker: creates a mail item, sets Subject and HTML body (R5), adds the single recipient and calls `Resolve()` (recording `to_resolved`), stamps a unique marker in a custom item property (`TodoRunId`), and calls `Send()`. Any exception becomes that recipient's `failed` with the error text **scrubbed of addresses and 8+ digit runs**; the run continues with the others. |
| R15 | **Proof of hand-over.** After `Send()` the worker looks, for up to `EMAIL_VERIFY_TIMEOUT` seconds (default 30, polling every 2 s), for an item carrying that run's marker in **Sent Items** (newest 25 items) → `delivery: accepted`; failing that, in the **Outbox** → `queued` (status stays `sent`); found nowhere → status `unconfirmed`, `delivery: pending`. |
| R16 | **Bounce detection.** After the last mail the worker waits `EMAIL_BOUNCE_WAIT` seconds (default 30), then scans the Inbox for reports received since the run began whose class ends in `.NDR` — a report is a **ReportItem, which has no `ReceivedTime` property, so its `CreationTime` is its arrival time** (found by T14: reading `ReceivedTime` raised and the report was silently skipped) — and whose text contains a recipient's address (compared in memory, case-insensitively, never logged) → that entry gets `delivery: bounced` and a `detail` "non-delivery report received". The scan always prints one stage line saying what it looked at — `bounce scan: N inbox item(s) in window, N non-delivery report(s), N unreadable, N matched` — so a scan that could not read what it found can never pass for "no bounce". `--reconcile` repeats the scan for every `live` `sent` entry of the last 3 days that is not yet `bounced` and appends one ledger row per newly found bounce; running it twice never duplicates a row. A bounce never changes `status` (idempotency is unchanged — a bounced person is **not** auto-resent to a wrong address). |
| R17 | Exit code: non-zero if any recipient is `failed` or `unconfirmed` or the run stopped early (`outlook-unavailable`, `send-timeout`, worker killed); zero otherwise — `bounced`, `queued`, `invalid_address` and skips do not fail the run, but are printed on stderr as lines starting `! ` so module 03 can decide how loudly to report them. |
| R18 | After every run, `outputs/04-email-message/send_log.json` is written (UTF-8, 2-space indent, `ensure_ascii=False`), prepending this run and keeping **every** run inside the last 30 days (a date may hold several runs). `trigger` is `schedule` \| `manual` \| `manual-ui` (default `manual`). |
| R19 | After the log, one row per entry is appended to the shared ledger `outputs/delivery/delivery_log.json` through `src/common/delivery_ledger.py` (same call as module 02 R26) with `channel: "email"`. A ledger failure prints `ledger: not written (<reason>)` on stderr and never changes the exit code. |
| R20 | No email address and no 8+ digit run appears in the log, the ledger, stdout/stderr, any committed file, or any error text. `src/EmailContent/` stays git-ignored (only `EmailContacts.sample.txt` with fake rows is tracked). `.secrets/email.env` holds no password because none exists. |
| R21 | Command-line options: `--people A,B` (send only to these `Person`s regardless of email days; everyone else is left out of the run entirely; an unknown name stops the run before anything is sent), `--resend` (only with `--people`: skip the `already_sent` check for them; entry logged `sent` with `resend: true`), `--trigger schedule\|manual\|manual-ui`, `--reconcile` (R16, sends nothing, may start Outlook), `--check` (prints settings with the address masked, Outlook's state — running / not running / classic missing — the profile **name withheld**, and whether the contacts parse; sends nothing, never starts Outlook), `--today YYYY-MM-DD` (tests). Without options behaviour is exactly R1–R20. |
| R22 | If `todo_by_name.json` is missing, unreadable, or not dated today (Asia/Dhaka) the run stops without sending, naming the file and the date found (reuses module 02's `read_todo`). |
| R23 | Two overlapping runs can never both send: the run takes `outputs/04-email-message/run.lock` with an **atomic create** (`O_CREAT\|O_EXCL`; JSON `{pid, started}`); a held lock is **stale** — and reclaimed — if its process is gone or it is more than 3 hours old; otherwise the run prints `skipped_locked` and why, sends nothing, writes no log row (the holder is rewriting the log) and exits 0. The lock is taken by every run that may send or start Outlook (`self`, `live`, `--reconcile`), not by `dry-run` or `--check`, and released in a `finally`. |

## 7. Steps / Design
Two Python processes, so a stuck Outlook can never wedge the caller (the lesson of module 02's worker hang, applied from day one):

- `.claude/skills/04-email-message/send_email.py` — **parent.** Owns config, inputs, schedule, message building (imports module 02's functions), idempotency, the lock, the logs, the ledger, the summary, and the hard ceiling. Never imports `win32com`.
- `.claude/skills/04-email-message/email_worker.py` — **worker.** Owns Outlook: readiness (R12), the per-recipient COM sequence (R14), proof (R15), bounce scan (R16). Reads a job file, writes a result file, prints stage lines with no address.

Dependency: `pywin32` (already installed; recorded in the SKILL's setup).

**Parent**
1. **Load config** from `.secrets/email.env` (`KEY=VALUE`, `#` comments, quotes stripped), real environment variables override; validate `EMAIL_MODE` (R9); `EMAIL_TEST_ADDRESS` required for `self` (R7). Never print a value in full. Parse the command line (R21): `--people`, `--resend`, `--trigger`, `--reconcile`, `--check`, `--today`; `--check` and `--reconcile` branch off here (`--check` prints the masked settings and Outlook's state and returns before step 2; `--reconcile` skips steps 3–7 and runs only the bounce scan of worker step 3 over the last 3 days).
2. **Take the lock** (R23) — except for `dry-run`. Held → print `skipped_locked`, exit 0.
3. **Read module 01 output** with module 02's `read_todo` (R22).
4. **Read contacts** (R1, R2, R3): `csv.reader(delimiter="\t")`; keep `Person` and the 4th field only; split the 4th on whitespace; validate the address (R2); `parse_days` for the rest.
5. **Load today's previous entries** from `send_log.json`: `live` rows only, statuses `sent` / `already_sent` / `unconfirmed` (R10).
6. **Decide per group** (R4, R10, R3, R2), union of module 01's groups and the contact list, A→Z, `No Name` last: no contact → `skipped_no_contact`; invalid address → `invalid_address`; already sent → `already_sent` (unless `--resend` and named by `--people`); day not today → `skipped_day` (ignored when `--people`); no items → `skipped_no_items`; else build the message (R5): `build_message(...)` for the text, then `render_html(text, signature)` for the body. The recipient is the person's own address in `live` (R8: nothing is set for From / SentOnBehalfOf, so Outlook's default account sends) and `EMAIL_TEST_ADDRESS` in `self` (R7).
7. **Cap** (R11); `dry-run` ends here (R6): each recipient `dry-run` with `subject` and `message`, Outlook untouched.
8. **Hand to the worker.** Write a job file (recipients' real addresses are in it, so it lives in the system temp dir — never the repo — and is deleted afterwards) and run `python email_worker.py <job> <result>` under the R13 ceiling; read the result back (also after a kill) and map each row onto a status and `delivery` (R14–R16).
9. **Write the log and ledger** (R18, R19); print the summary; release the lock; exit per R17. Before anything is printed or written, every string passes the scrubber of R20 (any address → `<address>`, any 8+ digit run → last four digits), including worker error text; the job file with real addresses is deleted in a `finally`.

**Worker**
1. **Outlook readiness** (R12): if no `OUTLOOK.EXE` process, `Popen([exe, "/profile", name])` minimised, poll `Dispatch` + `Session.GetDefaultFolder(5)` every 2 s up to `EMAIL_STARTUP_TIMEOUT`. `Dispatch` is *never* attempted while no process exists.
2. **Per recipient** (R14, R15): `item = app.CreateItem(0)`; `item.Subject`, `item.HTMLBody`; `item.Recipients.Add(address)`; `item.Recipients.ResolveAll()` → `to_resolved`; `item.UserProperties.Add("TodoRunId", 1)` = `<run id>-<n>`; `item.Send()`; then poll Sent Items (newest 25, by `SentOn` descending) for the marker, then the Outbox. Rewrite the result file after each recipient (temp file + rename); sleep the pause.
3. **Bounce scan** (R16): wait `EMAIL_BOUNCE_WAIT`; read Inbox items with `ReceivedTime >= run start` and `MessageClass` ending `.NDR` (using `CreationTime` as the arrival time of a report item); match recipient addresses in memory; record only `{person: bounced}` and print the one-line scan summary.
4. Exit 0 (or the reason code); the parent decides everything else.

**Message rendering (R5).** `render_html(text, signature)` HTML-escapes the text, converts each `\n` to `<br>`, appends two empty lines and the signature lines, and wraps everything in `<div style="font-family:Aptos,Calibri,Arial,sans-serif;font-size:12pt">…</div>`. The plain text of every message is stored in the log so the email can be compared with the WhatsApp one.

**Reuse, not copy.** `send_email.py` loads `send_whatsapp.py` from `.claude/skills/02-whatsapp-message/` with `importlib` and calls `read_todo`, `parse_days`, `build_message`. Importing it starts no worker and needs no WhatsApp settings (`load_config` is not called). Moving these helpers into `src/common/` is a possible later cleanup that would itself be a module 02 version bump; it is deliberately not part of this module.

## 10. Risks & Mitigations
| Risk | Impact | Mitigation |
|---|---|---|
| **Outlook is closed at 10:00 and a bare `Dispatch` blocks on "Choose Profile"** (reproduced) | The whole scheduled pipeline would hang | R12 never calls `Dispatch` without a running process and launches `/profile` itself; R13 puts all COM in a killable child with a hard ceiling; T13 and T23 prove both |
| Outlook's object-model security prompt ("a program is trying to send mail") appears | An unattended send would block on a dialog | Worker is bounded (R13); T11 proves whether the prompt fires on this machine before any live send; if it does, the owner decides between a trusted-add-in route and a different transport rather than this plan guessing |
| Mail stranded in the Outbox (Outlook offline, or closed too early) | The person never gets it though the log says sent | R15 reports `queued` instead of pretending; an Outlook this module started is left running; T16 |
| A mail is sent twice (scheduler + manual UI, or a retry) | A colleague gets duplicates | R10 live-only idempotency counting `unconfirmed`; R23 atomic lock; `--resend` is explicit and logged |
| A bounce is missed or misattributed | A wrong address is believed delivered | R16 matches the address inside the report in memory; `--reconcile` re-scans three days; unobserved so far on this mailbox, hence T14 with a throw-away address before relying on it |
| Real addresses or numbers leak into a log, plan or commit | Private data in a public repo | R1 discards the WhatsApp name/number unread; R20 scrubs everything; `src/EmailContent/` git-ignored; T20 greps |
| Outlook window pops up at 10:00 when the module starts it | Brief visual interruption | Started minimised; documented; leaving it running avoids repeating it |
| The WhatsApp text changes and the email follows | Unintended content change | Intended coupling (R5); the stored `message` field lets the owner compare both channels |
| New Outlook ("olk") replaces classic Outlook after an update | COM automation disappears | `--check` and the preflight say so plainly; out of scope to support (§5) |
| The signature/subject differ from what the owner wants later | Wrong wording | Both overridable in `.secrets/email.env` without a code change |

## 12. Troubleshooting & Rollback
| Symptom | Likely cause | Detect | Fix |
|---|---|---|---|
| Run stops: `outlook-unavailable` | Outlook did not become ready within `EMAIL_STARTUP_TIMEOUT` (profile problem, sign-in needed, or classic Outlook missing) | stderr reason; `--check` | Open Outlook by hand once and sign in; check `EMAIL_OUTLOOK_PROFILE`; raise `EMAIL_STARTUP_TIMEOUT` only if Outlook is merely slow. | A "Choose Profile" window sits on screen | Outlook was started without `/profile` (by hand, or by another program's COM call) | the window itself | Pick the profile once; the module itself always passes `/profile` (R12) |
| Entry `sent` / `delivery: queued` | Outlook was offline or had not synchronised within `EMAIL_VERIFY_TIMEOUT` | log; Outbox folder | Go online / let Outlook sync — it will send. Do **not** re-run (R10 would block it anyway) |
| Entry `unconfirmed` / `delivery: pending` | `Send()` returned but the message is in neither Sent Items nor Outbox within the timeout | log | **Check Sent Items by hand before doing anything.** Found → nothing to do. Not found → send by hand or clear the entry and re-run |
| A bounce is known to be in the Inbox but the run says `bounced: 0` | The scan could not read the report (it prints `N unreadable`) — e.g. an Outlook object-model difference for report items | the `bounce scan:` stage line | Run `--reconcile` after the fix; never treat "0 bounced" as proof when `unreadable` is not 0 |
| Entry `delivery: bounced` | The address is wrong or the mailbox is gone | the non-delivery report in the Inbox | Correct the address in `EmailContacts.txt` and send again from the manual UI with resend |
| `invalid_address` for someone | The 4th field holds no address, two addresses, or a typo | log status | Fix the row: one address, then the days, separated by spaces |
| Someone is not mailed though they have items | Email days exclude today, or they are not in `EmailContacts.txt` (WhatsApp contacts do not count) | log status `skipped_day` / `skipped_no_contact` | Edit the email file's days / add the row |
| An Outlook security prompt appears on send | Object-model guard active (antivirus not recognised as current) | the dialog; T11 | Stop live sending; see §10 — an owner decision, not a silent workaround |
| The mail's wording or layout is wrong | Subject/signature overridden in `.secrets/email.env`, or module 02's text changed | compare `message` in both logs | Fix the override, or the module 02 change was intended |
| Refuses to start | `EMAIL_MODE` missing or misspelled | stderr | Set `EMAIL_MODE` to `dry-run`, `self` or `live` |
| Run stops: stale module 01 output | Module 01 not run today | stderr shows the file date | Run skill `01-calendar-todo` first |
| `skipped_locked` | Another run (scheduler or manual UI) is in progress | log; `run.lock` | Wait for it; a lock from a dead process is reclaimed automatically |
| Log shows `worker killed after Ns` | The hard ceiling fired: Outlook or the worker wedged | stderr, last stage | Handled recipients are logged from the partial result; check Sent Items for the in-flight one before re-running |
